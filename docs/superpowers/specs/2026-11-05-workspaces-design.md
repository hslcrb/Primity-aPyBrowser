# Primity 0.3.0 — 분리된 계정, 익숙한 브라우저

## 목적과 수락 기준

Chrome의 Figma A 계정을 유지하면서 Primity의 B 계정을 독립적으로 쓰고, 필요하면 Primity에서도 여러 작업공간을 나란히 연다. 익숙한 탭·주소창·단축키와 흑백 디자인을 유지한다. 근거는 사용자가 지정한 IDEA_BANK 아이디어의 브라우저 요구다. 관련 없는 개인 메모는 복제하지 않는다.

1. 작업공간별 쿠키, Local Storage, IndexedDB, 서비스 워커, HTTP cache와 앱 북마크가 분리된다.
2. 같은 작업공간에서 새 탭·로그인 팝업은 같은 프로필을 사용한다. 다른 작업공간의 새 창은 별도 프로필을 사용한다.
3. 이름 변경에도 안정된 ID와 데이터 경로가 유지된다. 종료 후 영속 쿠키가 유지된다. 시크릿 창은 디스크에 세션을 저장하지 않는다.
4. 주소/검색, 뒤로/앞으로, 새로고침/중지, 탭 추가·닫기·복원, 찾기, 확대, 북마크, 다운로드, 작업공간 선택이 동작한다.
5. 웹 보안·sandbox·site isolation을 끄지 않는다. 인증서 오류와 권한 요청은 기본 거절이며 필요한 권한은 출처를 보여주고 선택한다.
6. Google 웹 로그인과 Chrome Sync를 구분한다. Qt에 Chrome Sync가 있다고 표시하지 않는다. 설치된 Google Chrome의 별도 user-data-dir을 여는 선택 기능으로 공식 로그인/동기화 경로를 제공한다.
7. 계정 정보의 자동 복사·공유, 비밀번호 평문 저장, 사이트 로그인 가로채기는 없다.
8. GitHub API, 헌법 형식 마이크로커밋, Workflows 금지, PR 없는 2부모 통합을 준수한다.

## 검토한 구현 방식과 결정

- **QtWebEngine 프로필 분리 + 선택적 Chrome 연결(채택)**: 기존 Python 앱을 유지하고 가벼운 브라우저 UX를 제공한다. 임베디드 브라우저를 거절하는 로그인은 별도 Chrome 창에서 사용한다. 이 선택은 구현 담당자의 판단이다.
- 전체 Electron 이식: 이 요구에는 큰 이식 비용이 있고 Chrome Sync 접근 제약도 해결하지 못한다.
- Chrome 실행기만 제공: 호환성은 좋지만 기존 Primity 브라우저 자체를 고도화하려는 목적을 충족하지 못한다.

## 구성

- `WorkspaceStore`: OS 앱 데이터 아래 UUID 기반 경로, 원자적 JSON 저장, 입력 검증, 프로필별 북마크·표시 설정. 손상된 파일은 덮어쓰지 않고 오류를 알린다.
- `ProfileRegistry`: 작업공간당 한 QWebEngineProfile, 경로 지정 후 페이지 생성, 새 시크릿 창마다 off-the-record 프로필. 앱 단일 실행 잠금으로 중복 프로세스가 같은 프로필을 열지 못하게 한다.
- `PrimityBrowser`: 창 하나에 작업공간 하나. 앱 컨트롤러가 다른 작업공간 창을 관리한다. 프로필을 살아 있는 페이지에서 바꾸지 않는다.
- `BrowserPage/View`: 같은 프로필의 새 탭/팝업, TLS 오류 거절, 권한 확인, 안전한 스킴만 탐색.
- `chrome_launcher`: 설치된 Chrome 탐색, 인자 배열 실행, 별도 `chrome` 데이터 경로. 일반 Chrome 프로필과 Qt 쿠키를 가져오거나 복제하지 않는다.

## 기존 코드와 변경 경계

기존 주 실행 경로의 전역 보안 우회, 전역 프로필, 모든 사이트에 노출한 WebChannel은 일반 작업 모드에서 제거한다. 아카이브 엔진과 관련 자산은 보존하되 일반 로그인 세션에 연결하지 않는다. 기존 평문 비밀번호 저장 기능은 새 브라우저 UI에서 제공하지 않는다. 기존 파일·기록은 자동 삭제하거나 이식하지 않는다. 북마크는 사용자가 명시적으로 선택한 JSON만 가져온다.

한국어/영어 UI, OS 기본 한글 입력, 다크/라이트 모드를 제공한다. 기존 커스텀 IME 코드는 보존하고 일반 사이트에는 자동 주입하지 않는다. 최소한의 native 창 테두리를 사용해 이동·크기 조절·접근성을 OS에 맡긴다.

## 검증과 실측 경계

순수 Python 테스트는 ID·경로·손상 데이터·원자적 저장·검색 URL·Chrome 인자 주입을 검증한다. Qt 통합 테스트는 실제 로컬 HTTP 사이트에서 A/B 쿠키·localStorage·IndexedDB·서비스 워커 분리, 팝업 프로필, 재시작 지속성, 기본 탐색을 검사한다. 테스트용 임시 프로필만 사용한다. 외부 계정 자격증명은 사용하지 않는다. Windows/macOS 및 실제 Google/Figma 인증 결과는 이 환경에서 직접 확인하지 못하면 미실측으로 남긴다.

분리는 브라우저 저장소 경계다. 같은 OS 계정의 악성 프로그램, 같은 IP나 사이트 서버가 의도적으로 연결하는 계정까지 격리하는 보안 경계라고 주장하지 않는다.
